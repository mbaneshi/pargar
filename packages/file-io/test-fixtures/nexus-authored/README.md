# NEXUS-authored DXF fixtures

These 10 DXF files are generated by `scripts/build-test-fixtures.mjs`. One fixture per AutoCAD 2D entity family that the parity sprint cares about. They cover the entity matrix listed in `docs/agent-tasks/ci-dxf-validators.md`:

| File | Entity | Notes |
|------|--------|-------|
| `line.dxf` | LINE | single segment |
| `polyline.dxf` | LWPOLYLINE | 4-vertex closed polyline |
| `circle.dxf` | CIRCLE | center + radius |
| `arc.dxf` | ARC | 90° sweep |
| `rectangle.dxf` | LWPOLYLINE (closed, 4 vertices) | NEXUS treats this as a Rectangle on import |
| `ellipse.dxf` | ELLIPSE | center, major axis, ratio 0.5 |
| `text.dxf` | TEXT | single-line, Standard style |
| `dimension.dxf` | DIMENSION (aligned) | references `Standard` dim style |
| `hatch.dxf` | HATCH | ANSI31 pattern, polyline boundary |
| `leader.dxf` | LEADER | 3-vertex straight leader |

## Why these are hand-authored, not exported from `exportDxf`

Test fixtures are ground truth. If `exportDxf` regresses, the round-trip diff should *catch* the regression — that means the fixtures must be independent of `exportDxf`'s current behavior. The generator emits raw DXF group codes via a small DSL helper inside the script itself.

## DXF version

R2000 (`AC1015`). Per `PRD.md` and `CLAUDE.md`, this is the v0.1 target.

## Byte-determinism

The generator writes no timestamps, handle counters, or random IDs. Re-running `node scripts/build-test-fixtures.mjs` produces byte-identical output, so CI audit reports are reproducible across runs.

## Updating fixtures

1. Edit `scripts/build-test-fixtures.mjs`.
2. Run `node scripts/build-test-fixtures.mjs` from the repo root.
3. `git diff packages/file-io/test-fixtures/nexus-authored/` to inspect the byte changes.
4. Commit both the script change and the regenerated `.dxf` files in one atomic commit.
